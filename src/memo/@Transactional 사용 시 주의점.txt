아래의 스프링이 제공하는 @Transcational을 통한 테스트 코드는 반드시 실패한다. 
그 이유는 @Transactional이 붙은 메서드 실행 시, 스프링은 트랜잭션 프록시 객체를 통해서 실행을 한다. 이때 트랜잭션 매니저/데이터 소스 등 트랜잭션 프록시에 필요한 의존관계를 바로 스프링 컨테이너에서 들고 온다. 
아래 코드는 순수 자바 코드의 테스트 코드이기에 @Transactional 실행 시 트랜잭션 프록시에 필요한 의존관계가 없으므로 당연히 실패한다. 
그래서 @SpringBootTest와 @TestConfiguration, @Bean을 통해 트랜잭션 프록시에 필요한 의존관계를 수동 등록해줘야 한다. 
 

class MemberServiceV3_3Test {

    public static final String MEMBER_A = "memberA";
    public static final String MEMBER_B = "memberB";
    public static final String MEMBER_EX = "ex";

    private MemberRepositoryV3 memberRepository;

    private MemberServiceV3_3 memberService;

    @BeforeEach
    void beforeEach() {
        // DriverManagerDataSource : DataSource 인터페이스의 JDBC 구현체
        DriverManagerDataSource dataSource = new DriverManagerDataSource(ConnectionConst.URL, ConnectionConst.USERNAME, ConnectionConst.PASSSWORD);
        this.memberRepository = new MemberRepositoryV3(dataSource);

        this.memberService = new MemberServiceV3_3(this.memberRepository);
   }

    @AfterEach
    void afterEach() throws SQLException {
        memberRepository.delete(MEMBER_A);
        memberRepository.delete(MEMBER_B);
        memberRepository.delete(MEMBER_EX);
    }

    @Test
    @DisplayName("정상 이체")
    void accountTransfer() throws SQLException {
        //given
        Member memberA = new Member(MEMBER_A, 10000);
        Member memberB = new Member(MEMBER_B, 10000);
        memberRepository.save(memberA);
        memberRepository.save(memberB);

        //when
        log.info("START TX");
        memberService.accountTransfer(memberA.getMemberId(), memberB.getMemberId(), 2000); // 여기에서는 같은 커넥션을 사용
        log.info("END TX");

        //then
        Member findMemberA = memberRepository.findById(memberA.getMemberId());
        Member findMemberB = memberRepository.findById(memberB.getMemberId());
        assertThat(findMemberA.getMoney()).isEqualTo(8000);
        assertThat(findMemberB.getMoney()).isEqualTo(12000);
    }

    @Test
    @DisplayName("이체 중 예외 발생(롤백 실행)")
    void accountTransferEx() throws SQLException {
        //given
        Member memberA = new Member(MEMBER_A, 10000);
        Member memberEx = new Member(MEMBER_EX, 10000);
        memberRepository.save(memberA);
        memberRepository.save(memberEx);

        //when
        assertThatThrownBy(() -> memberService.accountTransfer(memberA.getMemberId(), memberEx.getMemberId(), 2000))
                .isInstanceOf(IllegalStateException.class);

        //then
        Member findMemberA = memberRepository.findById(memberA.getMemberId());
        Member findMemberEX = memberRepository.findById(memberEx.getMemberId());
        assertThat(findMemberA.getMoney()).isEqualTo(10000);
        assertThat(findMemberEX.getMoney()).isEqualTo(10000);
    }
}



아래의 코드는 비지니즈 로직 호출(accountTransfer) 시, 제대로 트랜잭션 프록시 객체으로 트랜잭션이 호출됐는지 확인하기위함이다.
log.info("memberRepository.getClass() : ",memberRepository.getClass()) -> memberRepository class=class hello.jdbc.repository.MemberRepositoryV3
-> memberRepository는 일반 빈 객체이다.

log.info("memberService.getClass() : ",memberService.getClass()) -> memberService class=class hello.jdbc.service.MemberServiceV3_3$$EnhancerBySpringCGLIB$$...
-> 그러나 @Transactional을 붙인 memberService 객체는 MemberServiceV3_3$$EnhancerBySpringCGLIB, 즉 스프링에 의해서 프록시 객체화 돼 있다. @Transactional 실행을 위해 memberService 객체를 Ioc/DI 컨테이네서에서 꺼내와서
상속/오버라이드를 통해서 프록시객체를 생성한 것이다.
